# Starting point: five years of network security, zero Git

The user disclosed roughly five years of foundational network security study —
online college coursework plus self-study — and explicitly stated they are not a
coder. No prior Git or GitHub experience was claimed.

**Implications for teaching.** Explanations must not lean on programming
experience, and examples must never require reading application code; the only
code on screen should be Git itself. But the security background is a genuine
asset to exploit rather than ignore: hashing, integrity, chain-of-custody, and
access control are already familiar, so Git's tamper-evident history, branch
protection, and review gates can be taught as instances of concepts the user
already holds. Analogies should run *from* security *to* Git, not the reverse.
