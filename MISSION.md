# Mission: Git & GitHub

## Why

To build a public, verifiable track record on GitHub that supports a move into
cybersecurity, AI governance/risk/compliance (GRC), or AI training work. The
goal is not to become a software engineer — it is to be the person in the room
who can read a repository, follow a change through review, and speak the
language of version control fluently enough to audit it, teach it, or govern it.

Five years of network security coursework and self-study is the foundation.
GitHub is the missing surface where that knowledge becomes visible to employers.

## Success looks like

- Explaining out loud what a commit, branch, and pull request each are — without notes
- Creating a branch, committing to it, opening a pull request, and merging it, from memory
- Reading an unfamiliar repository and describing what changed, when, by whom, and why
- Recovering from the common Git failures (wrong branch, bad message, unwanted file) without panic
- Maintaining a profile README and at least one public repository worth showing an interviewer
- Reasoning about the *compliance* properties of a repo: audit trail, review gates, signed commits, branch protection

## Constraints

- Long, irregular sessions rather than daily practice — lessons must build in extra
  retrieval practice to compensate for weak spacing
- Not a coder. Explanations must not assume a programming background; any code
  that appears is Git itself, not application code
- No deadline. Prioritise long-term retention (storage strength) over fast progress

## Out of scope

- Writing application code in any language
- Advanced Git plumbing beyond what explains the mental model
- CI/CD pipeline authoring (revisit once the core flow is automatic)

## The longer arc

Two further topics were named as eventual destinations: **authoring Claude Code
skills** and **agent/LLM engineering**. Both sit downstream of this mission —
each is delivered through repositories, branches, and pull requests. They are
deliberately deferred, not abandoned. When Git and GitHub are automatic, that is
the signal to revisit the mission.
